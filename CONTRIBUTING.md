# Руководство по разработке

Этот проект разрабатывается силами нашего университетского клуба.
Мы используем стандартный Git Flow процесс для совместной работы.
Пожалуйста, внимательно ознакомьтесь с правилами ниже перед началом работы.


## 👥 Роли в проекте

• Мейнтейнеры (@core-maintainers): Проверяют Pull Requests, проводят код-ревью, следят за архитектурной целостностью и осуществляют финальный Merge в ветку main.

• Разработчики: Берут задачи, пишут код контейнеров, покрывают их тестами и создают PR.

## 🚀 Процесс разработки

1. Создание ветки: Не делайте Fork. Создавайте ветку прямо в этом репозитории от ветки development. Название ветки должно быть говорящим:
	• Для новых контейнеров: feature/vector-implementation
	• Для исправления багов: bugfix/fix-list-iterator
2. Написание кода и тестов: Реализуя контейнер, обязательно добавляйте соответствующие тесты в папку tests/. Убедитесь, что локально все тесты проходят.
3. Оформление Pull Request:
	• Создайте PR из вашей ветки в development.
	• В описании PR кратко укажите, что было сделано.
	• Назначьте (Assignee) себя и добавьте в качестве ревьюеров (Reviewers) команду мейнтейнеров.
4. Код-ревью: Мейнтейнеры проверят ваш код, запустят автоматические тесты (CI) и оставят замечания. После исправления замечаний и получения хотя бы одного одобрения (Approve), ваш код будет слит в development.

## 🎨 Стиль кода

Перед каждым коммитом обязательно оформите код с помощью clang-format, чтобы поддерживать единый стиль проекта.
